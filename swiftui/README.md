## Building the sample app

`Lemonade.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
and not checked in. Generate it with:

```bash
cd swiftui && ./scripts/generate-ios-project.sh
```

Re-run it after changing `project.yml`, and after adding or deleting a file under
`SampleApp/` or `Sources/` — a stale project fails with "Build input file cannot
be found".

Then open `Lemonade.xcodeproj` and run the **LemonadeSampleApp** scheme.

### iOS code signing (physical device)

Simulator builds need no signing. Device builds need your Apple Developer Team
ID, which lives in `Local.xcconfig` — gitignored, so it never reaches this
repository.

The generate script creates that file for you and fills in the Team ID when it
finds exactly one signing certificate in your keychain, so usually there is
nothing to do. If it reports the field was left empty:

1. Find your Team ID (it is the `OU` field):

   ```bash
   security find-certificate -a -c "Apple Development" -p | openssl x509 -noout -subject
   ```

2. Set it in `swiftui/Local.xcconfig`:

   ```
   DEVELOPMENT_TEAM = YOUR_TEAM_ID_HERE
   ```

3. Regenerate:

   ```bash
   ./scripts/generate-ios-project.sh
   ```

Don't set the team through Xcode's **Signing & Capabilities** editor. It only
changes the generated project, so the next regeneration wipes it and device
builds fail again with "Signing for LemonadeSampleApp requires a development
team".

The Team ID is deliberately not committed: this repository is public, and pinning
one would make every fork sign against an organisation its contributors don't
belong to.
